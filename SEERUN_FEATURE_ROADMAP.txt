FEATURE 1: Algorithm Template Library
--------------------------------------
  Problem  : Users open a blank editor. They don't know what to write.
  Solution : A modal/drawer with 30+ pre-built algorithm templates
             grouped by category. User taps one → code loads instantly.
  
  Categories to include:
    Linked List   → Reverse, Detect Cycle, Clone, Find Middle, Merge Two
    Arrays        → Binary Search, Two Pointers, Sliding Window, Kadane
    Trees         → Inorder, Preorder, BFS Level Order, Height, LCA
    Graphs        → BFS, DFS, Dijkstra, Topological Sort, Flood Fill
    Sorting       → Bubble Sort, Merge Sort, Quick Sort, Heap Sort
    Dynamic Prog  → Fibonacci, 0/1 Knapsack, LCS, Coin Change
    Stacks/Queues → Valid Parentheses, Monotonic Stack, Circular Queue
    Math          → GCD, Sieve of Eratosthenes, Fast Exponentiation

  Files to change:
    - app/index.tsx         → Add Template Picker modal button + modal UI
    - data/templates.ts     → [NEW] All template code strings organized by category
  
  Effort: Medium | Impact: VERY HIGH


FEATURE 2: Auto-Play + Playback Speed Control
----------------------------------------------
  Problem  : Users must tap "Next" 50+ times for long algorithms.
             There is no way to watch execution flow automatically.
  Solution : An Auto-Play button (▶ / ‖) that steps through execution
             at a configurable speed. A speed selector: 0.5x 1x 2x 5x.

  Files to change:
    - app/visualizer.tsx    → Add `isPlaying` state, `playbackSpeed` state
                              Add setInterval-based auto-stepper
                              Add speed selector buttons in control bar

  Effort: Small | Impact: VERY HIGH


FEATURE 3: Step Counter + Progress Bar
----------------------------------------
  Problem  : Users have no sense of where they are in the execution.
             Is step 7 near the start or near the end? Unknown.
  Solution : Display "Step 7 of 43" in the header.
             A thin colored progress bar below the CODE header.

  Files to change:
    - app/visualizer.tsx    → Expose total trace length, compute progress %
                              Render progress bar and step counter in header

  Effort: Small | Impact: HIGH


FEATURE 4: Variable Change Log (Diff per Step)
------------------------------------------------
  Problem  : The variables panel shows current state but NOT what changed.
             Users have to mentally diff every step themselves.
  Solution : A small log section under variables panel showing:
               "Step 5: slow  0 → 1"
               "Step 5: fast  0 → 2"
             Only changed variables shown, with old → new value.

  Files to change:
    - app/visualizer.tsx    → Deep compare prev/curr state each step
                              Render change log entries with styled arrows

  Effort: Small | Impact: HIGH


FEATURE 5: Friendly Error Explanation Engine
---------------------------------------------
  Problem  : JSCPP throws cryptic errors like "Parsing Failure: line 4"
             or "variable cout does not exist". Users are completely lost.
  Solution : A pattern-matching engine that maps known error strings
             to plain English explanations + actionable fix suggestions.

  Error mapping examples:
    "variable cout does not exist"
      → "Add 'using namespace std;' at the top of your code."
    "Parsing Failure" + "ListNode"
      → "JSCPP cannot parse struct constructors. Use a createNode() helper function instead."
    "Parsing Failure" + ";;"
      → "Double semicolon detected. Your struct definition has an extra semicolon."
    "Infinite execution loop"
      → "Your loop has no exit condition. Check your while loop termination."
    "Compilation Error: ERROR"
      → Show the raw error line + suggest checking the line number mentioned.

  Files to change:
    - app/visualizer.tsx    → Add `friendlyError(msg: string): string` helper
                              Replace raw error display with friendly version

  Effort: Small | Impact: HIGH

FEATURE 6: Breakpoints
------------------------
  Problem  : For 100-line algorithms, users want to skip to line 60
             without clicking "Next" 60 times.
  Solution : Tap any line number → red dot appears (breakpoint set).
             Press Play → execution runs automatically and PAUSES
             when it hits a breakpointed line.
             Tap again → breakpoint removed.

  Files to change:
    - app/visualizer.tsx    → `breakpointLines: Set<number>` state
                              Check breakpoints during auto-play loop
                              Render red dots on line number column

  Effort: Medium | Impact: HIGH


FEATURE 7: Save & History
--------------------------
  Problem  : Users write great code, close the app, it's gone forever.
  Solution : Auto-save last 10 dry runs using AsyncStorage.
             A "History" screen shows: algorithm name, language,
             timestamp, code preview. Tap to reload any saved run.
             Users can also manually name and star a dry run.

  Files to change:
    - app/history.tsx       → [NEW] History screen with list of saved runs
    - utils/storage.ts      → [NEW] AsyncStorage read/write helpers
    - app/index.tsx         → Add "Save" button + auto-save on run
    - app/_layout.tsx       → Add History tab to navigation

  Effort: Medium | Impact: HIGH


FEATURE 8: Expected Output Diff
---------------------------------
  Problem  : Users can't tell if their algorithm produces the right answer.
  Solution : An "Expected Output" text box on the editor screen.
             After execution, compare expected vs actual console output.
             Show a ✅ PASS or ❌ FAIL badge with a side-by-side diff.

  Files to change:
    - app/index.tsx         → Add `expectedOutput` TextInput field
    - app/visualizer.tsx    → Compare final outputBuffer to expectedOutput
                              Render PASS/FAIL badge with diff view

  Effort: Small | Impact: HIGH


FEATURE 9: Variable Pin / Watch Window
----------------------------------------
  Problem  : When there are 20 variables, the ones you care about
             (e.g., slow, fast, head) get buried by internal variables.
  Solution : Long-press any variable name → it gets "pinned" to a
             sticky "WATCH" section at the very top of the variables panel.
             Pinned variables always stay visible regardless of scroll.

  Files to change:
    - app/visualizer.tsx    → `pinnedVars: string[]` state
                              Render separate "WATCH" section for pinned vars
                              Long-press handler on variable rows

  Effort: Small | Impact: HIGH


FEATURE 10: Syntax Highlighting in Editor

  Files to change:

  Effort: Large | Impact: HIGH

FEATURE 16: Visual Data Structure Panel
-----------------------------------------
  Problem  : Seeing "val[0]=10, nxt[0]=1, val[1]=20" is not intuitive.
             Users need a graphical representation of the data structure.
  Solution : A dedicated visual panel that auto-renders based on
             the variable names and types present:
               int[] / val[] + nxt[]  →  Linked List with arrows
               parent[]               →  Disjoint Set (Union Find) tree
               stack[]                →  Vertical tower of boxes
               queue[]                →  Horizontal conveyor lane
               adj[][]                →  Graph nodes and edges
             The visualization animates in sync with execution steps.

  Files to change:
    - components/DataStructureVisualizer.tsx → [NEW] Canvas/SVG renderer
    - app/visualizer.tsx                     → Pass current vars to renderer
                                               Show/hide panel toggle

  Effort: Very Large | Impact: VERY HIGH


FEATURE 17: Binary Tree Visualizer
------------------------------------
  Problem  : BST, AVL, Segment Tree are among the most common interview topics.
             Without visual rendering, they're impossible to understand from vars alone.
  Solution : When user declares `int tree[4*N]` or an array-based binary tree,
             render proper tree with:
               - Circular node boxes with values
               - Lines connecting parent to left/right child
               - Current node highlighted in execution color
               - BFS/DFS traversal animated hop by hop

  Files to change:
    - components/TreeVisualizer.tsx  → [NEW] SVG-based tree renderer
    - app/visualizer.tsx             → Detect tree pattern, mount visualizer

  Effort: Very Large | Impact: VERY HIGH


FEATURE 18: Graph BFS / DFS Visualizer
----------------------------------------
  Problem  : Graph algorithms are the #1 topic in technical interviews
             but the hardest to visualize without a proper graph diagram.
  Solution : When user uses a 2D adjacency matrix `int adj[N][N]`,
             render a force-directed graph with:
               - Circular nodes with IDs
               - Lines (edges) between connected nodes
               - Visited nodes highlighted in a trail color
               - Queue/Stack state shown beside the graph

  Files to change:
    - components/GraphVisualizer.tsx → [NEW] Graph layout + animation engine
    - app/visualizer.tsx             → Detect adj matrix pattern, mount renderer

  Effort: Very Large | Impact: VERY HIGH


FEATURE 19: Sorting Animation Panel
-------------------------------------
  Problem  : Sorting algorithms are the first thing every CS student learns.
             Visual bar charts are the most iconic CS education visualization.
  Solution : When user runs a sorting algorithm, detect the primary array
             and render animated bars:
               - Each element = a bar, height proportional to value
               - Compared elements highlighted in yellow
               - Swapped elements flash red → green
               - Final sorted state glows green

  Files to change:
    - components/SortingVisualizer.tsx → [NEW] Bar chart animation component
    - app/visualizer.tsx               → Detect sorting pattern, mount renderer

  Effort: Large | Impact: HIGH


FEATURE 20: Java Language Support
-----------------------------------
  Problem  : Millions of CS students use Java (Android dev, university courses).

  Files to change:

  Effort: Very Large | Impact: HIGH


BONUS FEATURE 21: AI "Explain This Step" Button
--------------------------------------------------
  Problem  : A variable changes from 3 to 7. Users don't know WHY.
  Solution : A small brain icon (🧠) next to each changed variable.
             Tap it → sends current code + execution context to an LLM API.
             Returns a plain English explanation:
               "fast moved to index 2 because the while loop condition
                'fast != -1 && nxt[fast] != -1' was still true, so
                fast advanced two nodes in the linked list."

  Files to change:
    - utils/ai.ts           → [NEW] LLM API call (OpenAI / Gemini API)
    - app/visualizer.tsx    → 🧠 button on variable change rows
    - app/settings.tsx      → API key input for user's own key

  Effort: Medium | Impact: VERY HIGH (differentiator feature)
